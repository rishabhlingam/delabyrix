### The core fix — strict if/elif/else state machine + `st.rerun()` on every non-terminal branch

The DOM-dimming bug is a Streamlit fundamental: **elements drawn in a previous script pass persist in the browser as "dimmed" until the current pass finishes**. No `placeholder.empty()` call can clear them mid-pass because Streamlit batches DOM updates and applies them only when the full script completes. The only way to guarantee the browser never sees stale content alongside new content is to ensure **the same script pass never both clears old state and renders new content** — the new content must appear in a *later* pass, after the clearing pass has completed cleanly.

The state machine enforces this:

**Branch 1 — Submit clicked:**
- Calls `_clear_output_state()` → all output keys are `None`
- Fires the POST synchronously (spinner is fine here — it's the *only* thing drawn this pass)
- Stores result keys in `st.session_state`
- Calls `st.rerun()` → Streamlit completes this pass (browser sees: form + spinner, nothing else), then starts a fresh pass

**Branch 2 — `pending_session_id` set (polling pass):**
- Draws *only* the blue info banner — `response_text`, `pipeline_trace`, `rejected_info` are all `None` so no old response can appear
- Makes one `GET /agent/session/...` call
- On `approved`/`rejected`: stores result, clears `pending_session_id`, calls `st.rerun()`
- On `pending`: `time.sleep(3)` then `st.rerun()` — the sleep is safe here because this pass already has nothing to clear; the banner is the only thing drawn

**Branches 3/4/5 — terminal render:** draw exactly one of: rejection alert, response+trace, or error — then stop. No `st.rerun()` needed.

The `elif` chain between branches 2–5 is a hard invariant: **exactly one branch fires per pass**, so the browser never sees two mutually exclusive states in the same DOM snapshot.
