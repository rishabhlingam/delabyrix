Implement bilingual HITL review support, bidirectional translation toggles, and updated approval/rejection displays across the backend and React frontend—while leaving the 4 teammate starter areas (`HomePage.tsx`, `index.html`, `seed_demo_data.py`, and the `AppShell.tsx` footer) untouched.

### 1. Backend HITL & Session Bilingual Payload Support (`backend/`)
Inspect `backend/routers/hitl.py`, `backend/routers/agent.py`, `backend/services/hitl_manager.py` (or SQLite persistence layer), and `backend/models/`:
- **Preserve Original & English Texts:** Ensure every HITL item (`GET /hitl/queue`) and session status response (`GET /agent/session/{session_id}`) includes:
  - `source_language` (e.g., `"es"`, `"hi"`, `"en"`)
  - `redacted_original_text` (or `original_inquiry` with PII stripped) AND `english_inquiry` (the English translation)
  - `draft_response_original` (generated in `source_language`) AND `draft_response_english`
  - `rejection_reason` (as submitted by the reviewer) AND `rejection_reason_english` / `rejection_reason_original`
- **Bidirectional Translation Endpoint:** Add a clean endpoint `POST /agent/translate` (or `POST /hitl/translate`) accepting `{ "text": string, "source_lang": string, "target_lang": string }` that uses the existing translation / watsonx helper (with deterministic mock-mode fallback so `pytest` works offline without API calls) so clinicians or patients can translate any custom-edited draft or rejection note both ways (`non-English -> English` and `English -> non-English`).
- **Session Rejection Reason:** Ensure `POST /hitl/reject` persists `rejection_reason` to SQLite and `GET /agent/session/{session_id}` returns `rejection_reason` (plus its translated variant) whenever `status == "rejected"`.

### 2. Update `HITLReviewPage.tsx` (Carbon Inline Toggles & Original-Language Defaults)
Follow `.bob/rules-agent/ui-design-system.md` strictly (use `@carbon/icons-react` `Translate` icon at `h-3.5 w-3.5` with `text-xs font-medium text-[#0f62fe] hover:underline` inside `rounded-none` Carbon cards/wells):
1. **Patient Inquiry Box:**
   - Display the patient's redacted inquiry in its **original language** by default.
   - When `source_language !== "en"`, place a native toggle button on the **top-left corner** of the Patient Inquiry well labeled **`Translate to English`** (when viewing original) and **`Show Original (<UPPERCASE_LANG>)`** (when viewing English), toggling cleanly both ways.
2. **Draft Response Field:**
   - Default the Draft Response content/textarea to the **original language** (`source_language`).
   - Place the same bidirectional toggle (**`Translate to English`** ↔ **`Show Original (<UPPERCASE_LANG>)`**) on the **top-left corner** of the Draft Response box, translating custom clinician edits via `POST /agent/translate` if edited.
3. **Reject Flow:**
   - When clicking **Reject**, pre-fill the rejection reason box with a polite default rejection message in the patient's **original language** (`source_language`), with the same bidirectional **`Translate to English`** ↔ **`Show Original (<UPPERCASE_LANG>)`** toggle on the **top-left corner** of the rejection box.

### 3. Update `PatientAssistantPage.tsx` & `src/lib/i18n.ts`
1. **Concise Status Labels:**
   - Change `"Response Rejected"` to **`"Rejected"`** and `"Response Approved"` (or approved banner title) to **`"Approved"`** (update both `PatientAssistantPage.tsx` and `src/lib/i18n.ts`).
2. **Rejection Reason Display with Bidirectional Translate:**
   - When a query is `REJECTED`, display a **Rejection Reason** well below the status header showing the exact reason entered by the reviewer.
   - Place a bidirectional toggle button on the **top-left corner** of the Rejection Reason well (`Translate` icon, `text-xs font-medium text-[#0f62fe] hover:underline`):
     - If the reviewer wrote in a non-English language, show **`Translate to English`** ↔ **`Show Original (<LANG>)`**.
     - If the reviewer wrote in English for a non-English query (`source_language !== "en"`), show **`Translate to <LANGUAGE_NAME>`** ↔ **`Show Original (EN)`** so the patient can read it in their own language or switch back to English.

### 4. Verification

 *
 * Strategy: take the first sentence of the draft (which typically states the
 * key clinical finding, e.g. "Metamizole is restricted in the US due to …"),
 * strip any numbered-list preamble, then append a short action line in the
 * appropriate language.  Falls back to a generic message when the draft is
 * empty or too short to extract a meaningful sentence.
 */
function buildSpecificRejection(draftResponse: string, lang: string): string {
  const suffix = REJECTION_SUFFIX[lang.toLowerCase()] ?? REJECTION_SUFFIX["en"];
  const generic = GENERIC_REJECTION[lang.toLowerCase()] ?? GENERIC_REJECTION["en"];

  if (!draftResponse || !draftResponse.trim()) return generic;

  // Strip leading list markers like "1." or "•" and normalise whitespace
  const cleaned = draftResponse
    .replace(/^\s*[\d]+[.)]\s*/gm, " ")
    .replace(/\s+/g, " ")
    .trim();

  // Extract up to the first sentence-ending punctuation (. ! ?)
  const match = cleaned.match(/^(.{20,}?[.!?])/);
  if (!match) return generic;

  const firstSentence = match[1].trim();
  // Guard against extracting a sentence that is a numbered-list artefact
  // (pure digits + punctuation with no real words)
  if (firstSentence.length < 20) return generic;

  return `${firstSentence} ${suffix}`;
}
