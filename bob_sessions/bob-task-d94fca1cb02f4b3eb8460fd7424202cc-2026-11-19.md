### Fix 1 — Rosiglitazone/DE escalation gap ([`medical_interpreter.py`](backend/pipeline/medical_interpreter.py:146))

**Root cause:** `rosiglitazone` was absent from `_KNOWN_INNS`, and the heuristic regex only captures words near context keywords. The brand name `Avandia` was never mapped to its INN. **Fix:** Added `"rosiglitazone"`, `"domperidone"`, and `"phenylephrine"` to `_KNOWN_INNS` (direct scan regardless of proximity to context words), and added `"avandia" → "rosiglitazone"` and `"vioxx" → "rofecoxib"` to `_INN_ALIASES` so brand-name mentions are normalized to their INN before the registry call.

---

### Fix 2 — Substring collision in registry lookup ([`query.py`](backend/registry/query.py:29))

**Root cause:** The single-pass loop used `query in _normalise(name_generic)` — substring matching. `"ibuprofen"` is a substring of `"ibuprofen lysinate"` (banned in US_FDA), so the standard drug hit the banned record first.

**Fix:** Restructured [`check_medication()`](backend/registry/query.py:29) into two passes: **Pass 1** tries exact case-insensitive equality (`==`) on both `name_generic` and `name_brand`; **Pass 2** falls back to substring matching only when no exact match exists. `"ibuprofen"` now correctly hits the exact `"ibuprofen"` record (approved) and never reaches the `"ibuprofen lysinate"` entry.

---

### Fix 3 — WatsonxClient migrated to `/ml/v1/text/chat` ([`client.py`](backend/watsonx/client.py:255))

**Root cause:** Real-mode calls used `model.generate(prompt=chat_prompt, ...)` with manually crafted Granite role-tag strings, which triggers `WatsonxAPIWarning` deprecation warnings.

**Fix:** Replaced with `model.chat(messages=[{"role": "system", ...}, {"role": "user", ...}], params=...)` extracting `raw["choices"][0]["message"]["content"]`. Removed the now-unnecessary `_build_granite_chat_prompt()` helper, `_GRANITE_STOP_SEQUENCES` constant, and the manual role-tag string formatting. Updated `_estimate_confidence()` to handle both the chat response format (`choices[0].logprobs.content`) and the legacy format.

---

### Fix 4 — G6 diagnostic test uses delta check ([`run_live_diagnostics.py`](scripts/run_live_diagnostics.py:800))

**Root cause:** `pending_count == 0` assumed the queue was empty before the test, which fails when other concurrent tests left pending items.

**Fix:** Snapshots `pre_count = pending_count` immediately before the approval call, then verifies `post_count == pre_count - 1` — robust regardless of how many other items are in the queue at that moment.
